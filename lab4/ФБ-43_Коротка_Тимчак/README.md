# Лабораторна №4 — RSA, цифровий підпис і передавання ключа

**Бригада:** ФБ-43, Коротка Ксенія та Тимчак Анастасія.

Робота виконана відповідно до оновленої методички КП №4. Окремого варіанта немає. Генеруються чотири прості числа по **256 біт**, ключові модулі — по **512 біт**; використано **e = 65537**. Алгоритми побудовані на стандартній бібліотеці Python; готові криптографічні бібліотеки та готові тести простоти не використовуються.

## Файли

- `lab4.py` — пробні ділення, власний тест Міллера–Рабіна, схема Горнера, розширений алгоритм Евкліда, генерація параметрів та 7 обов'язкових процедур: `GenerateKeyPair`, `Encrypt`, `Decrypt`, `Sign`, `Verify`, `SendKey`, `ReceiveKey`.
- `sample_run.json` — числові значення вже виконаного експерименту для точного відтворення звіту.
- `keys.json` — відкриті та секретні RSA-ключі цього експерименту для A і B.
- `results.txt` — вивід режиму `--sample`; містить 20 реально використаних основ повторної перевірки `p1` та проміжні значення однієї з них.
- `candidates.txt` — 161 відхилений кандидат із зазначенням причини; послідовність кандидатів відновлено з історичного прикладу та перевірено її розподіл: 131 пробними діленнями, 30 Міллером–Рабіном.
- `server_check.py` — ручні перевірки з тестовим сайтом у шістнадцятковому форматі.
- `server_check.txt` — початкові числові значення операцій із сайтом.
- `screenshots/` — вісім початкових скриншотів тестового середовища.
- `test_lab4.py` — 9 автоматичних тестів, включно з негативними випадками та локальною перевіркою серверних результатів.
- `Lab4_Korotka_Tymchak.pdf` — виправлений звіт (13 сторінок) у початковому оформленні Насті.
- `FIXES.md` — перелік усіх виправлень.

## Запуск

Із папки лабораторної:

```bash
python3 lab4.py --sample
python3 -m unittest -v test_lab4.py
python3 server_check.py pub
```

`--sample` **не змінює числові значення**, що вже є в PDF і скриншотах. Він повторно перевіряє записані прості числа, зберігає використані основи Міллера–Рабіна і повторює арифметичні операції RSA для тих самих M та k. Це рекомендований режим для захисту.

Для повністю нового випадкового експерименту:

```bash
python3 lab4.py
```

Якщо додати `--save`, файли `results.txt`, `candidates.txt`, `keys.json` **будуть перезаписані**. Не запускайте `python3 lab4.py --save` перед здачею, якщо хочете зберегти відповідність уже підготовленому звіту. Відтворити його можна командою `python3 lab4.py --sample --save`.

## Приклади взаємодії із сервером

```bash
python3 server_check.py pub
python3 server_check.py encrypt M server_n server_e
python3 server_check.py decrypt C
python3 server_check.py sign M
python3 server_check.py verify M S server_n server_e
python3 server_check.py send k server_n server_e
python3 server_check.py receive k1 S1 server_n server_e
```

Всі параметри тут вводяться в **hex** (можна без `0x`). Потрібно скопіювати відповідні числа з сайту `http://asymcryptwebservice.appspot.com/?section=rsa` та його форми. Скрипт не надсилає дані автоматично. Початкові серверні значення перевірено локально в `test_lab4.py`; нові перевірки з вебсайтом не заявляються.

## Важливо

RSA в методичці — навчальний RSA без доповнення (padding). **Не використовуйте цю реалізацію для реального захисту даних.** Секретні ключі у `keys.json` оприлюднені лише як частина демонстраційного прикладу.
