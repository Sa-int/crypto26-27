# Лабораторна 4 — Криптосистема RSA, цифровий підпис і протокол розсилання ключів

**Бригада:** ФБ-43 — Коротка, Тимчак

Окремих варіантів немає: усі числа генеруються випадково. Прості — 256 біт, модулі n, n₁ — 512 біт, e = 2¹⁶ + 1.

## Файли

- `lab4.py` — власні реалізації: розширений алгоритм Евкліда, піднесення до степеня за схемою Горнера, пробні ділення, тест Міллера-Рабіна (20 основ), пошук випадкового простого; сім процедур `GenerateKeyPair`, `Encrypt`, `Decrypt`, `Sign`, `Verify`, `SendKey`, `ReceiveKey`. Друкує результати в консоль; з прапорцем `--save` також записує `results.txt`, `candidates.txt`, `keys.json`.
- `results.txt` — результати запуску: p, q, p₁, q₁ з відкинутими кандидатами, проміжні значення тесту Міллера-Рабіна, ключі A і B з перевіркою співвідношень, шифрування й підпис, протокол передачі ключа.
- `candidates.txt` — усі відкинуті кандидати із зазначенням, яку перевірку вони не пройшли.
- `keys.json` — ключі абонентів A і B.
- `server_check.py` — перевірка з тестовим середовищем http://asymcryptwebservice.appspot.com/?section=rsa (hex на вході й виході, ключ абонента A).
- `server_check.txt` — значення, використані під час перевірки; `screenshots/` — скріншоти.
- `lab4_Korotka_Tymchak.docx` / `.pdf` — звіт (протокол).

## Запуск

```bash
cd lab4/ФБ-43_Коротка_Тимчак
python3 lab4.py                      # новий запуск, лише друк у консоль (файли не змінюються)
python3 lab4.py --save               # перезаписати results.txt, candidates.txt, keys.json
python3 server_check.py pub          # наш відкритий ключ у hex
python3 server_check.py decrypt <C>  # інші команди — у заголовку server_check.py
```

## Основні результати

- Для кожного простого перевірено 17–54 кандидати; більшість складених відсіяно пробними діленнями, решту — тестом Міллера-Рабіна.
- Для ключів A і B: gcd(e, φ(n)) = 1, e·d mod φ(n) = 1, n ≤ n₁. Розшифрування повертає M, а підпис перевіряється тільки для незміненого повідомлення.
- Протокол A → B: B отримав той самий k і підтвердив підпис A.
- Тестове середовище: усі операції пройшли перевірку в обидва боки. Для отримання ключа сервером узято його 1024-бітний ключ, бо потрібно n ≤ n сервера.
